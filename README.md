# PulseBoard

PulseBoard is a small portfolio analytics dashboard demonstrating a React + TypeScript frontend with a simple ASP.NET Core Web API backend. It provides basic product metrics, an active users chart, and a recent events table with client-side filtering.

## Features
- Metric summary cards (active users, conversion rate, revenue, page views)
- Active users line chart with period selection (7/14/30 days)
- Recent events table with platform filtering (All/Web/Mobile)
- Loading skeleton, error state with retry, and empty states
- Responsive layout and basic accessibility improvements

## Technologies
- Frontend: React, TypeScript, Vite, Tailwind CSS, Recharts
- Backend: ASP.NET Core Web API (C#)

## Architecture overview
- Frontend (`pulseboard-client`): Single-page React app. `useAnalytics` hook fetches `/api/dashboard` data and provides `data`, `isLoading`, `error`, and `refetch`.
- Backend (`PulseBoard.Api`): Minimal ASP.NET Core Web API exposing endpoints that return dashboard summary, chart data, and recent events.

## Folder structure
- `pulseboard-client/` — frontend source and build files
- `PulseBoard.Api/` — backend source

## Running locally
Prerequisites: Node.js (recommended 22.13.0+) and .NET SDK (8.0+).

### Backend
From the repository root:
```bash
cd PulseBoard.Api
dotnet run
```
Default local URL: `https://localhost:5001` (or as printed by the app). API endpoint used by the frontend: `/api/dashboard` (relative to the backend base URL).

### Frontend (development)
From the repository root:
```bash
cd pulseboard-client
npm install
npm run dev
```
Local dev URL: `http://localhost:5174/` (Vite may pick a different port if 5173 is in use).

### Frontend (production preview)
```bash
cd pulseboard-client
npm run build
npm run preview
```

## Build commands
- Frontend typecheck: `./node_modules/.bin/tsc --noEmit`
- Frontend build: `npm run build`
- Backend build: `dotnet build`

## API endpoint
- `GET /api/dashboard` — returns dashboard summary, chartData, and recentEvents (see `PulseBoard.Api` DTOs).

## Key engineering decisions
- Keep UI logic in the frontend; backend serves read-only analytics DTOs.
- Use a lightweight custom hook (`useAnalytics`) to encapsulate data fetching and refetch behavior.
- Prioritize small, reusable components (`MetricCard`, `EventsTable`) for clarity and accessibility.

## Future improvements
- Add pagination or server-side filtering for large event lists
- Code-splitting for large bundles and lazy-loading of non-critical parts
- Integration tests and E2E tests for critical flows

## Cleanup recommendations (safe to remove)
- `pulseboard-client/dist/` — production build output; safe to remove if you want a smaller repo copy.
- `Pulseboard-client-backup/` — duplicate/backup of the frontend; review and remove if redundant.

## Manual final test checklist
1. Start backend: `cd PulseBoard.Api && dotnet run`
2. Start frontend dev: `cd pulseboard-client && npm install && npm run dev`
3. Open the app at the dev URL (e.g., `http://localhost:5174/`)
4. Verify loading skeleton by throttling network or adding delay in the service
5. Verify error and retry by making the backend unavailable and pressing Try again
6. Test filters: change Period (7/14/30) and Platform (All/Web/Mobile)
7. Test empty states by returning empty `chartData` or selecting a platform with no events
8. Test responsiveness and keyboard navigation (Tab through selects and buttons)
